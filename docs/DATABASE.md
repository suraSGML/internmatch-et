# InternMatch ET — Database Documentation

## Overview

PostgreSQL database hosted on Supabase. All tables have Row Level Security (RLS) enabled. Migrations live in `supabase/migrations/` and run in numbered order.

## Key Tables

### `profiles`
One row per `auth.users`. Stores role (`student`, `company`, `university`, `admin`), name, phone, city. Created automatically by `handle_new_user` trigger on signup.

### `student_profiles`
Extended student data. JSONB columns:
- `skills`: `[{name, level}]`
- `languages`: `[{language, level}]`
- `links`: `{github, linkedin, portfolio}`
- `availability`: `{start_date, duration_weeks, modes[]}`

### `internships`
Core listing. `required_skills` is a JSONB array `[{name, level?}]`. `filled_slots` is incremented atomically by the `handle_offer_accepted` trigger when an offer is accepted — over-allocation is prevented with a `FOR UPDATE` row lock.

### `applications`
Unique constraint on `(internship_id, student_id)` prevents duplicate applications. Status transitions are logged automatically by `record_application_event` trigger.

### `placements`
Created after an offer is accepted. `status` flows: `pending_approval → approved → active → completed`. University approval is required when `internships.requires_university_approval = TRUE`.

### `logbook_entries`
One entry per week (`UNIQUE(placement_id, week_start)`). `get_logbook_summary(placement_id)` returns aggregated hours and approval rate as JSONB.

### `certificates` / `placement_letters`
Each has a `public_code` (format `IM-XXXXXXXX`) generated by `generate_public_code()`. The `verify_document(code)` function is granted to `anon` role for the public verification page — it returns only non-sensitive fields.

### `audit_logs`
Append-only. PostgreSQL `RULE` prevents UPDATE and DELETE. Written via `write_audit_log()` SECURITY DEFINER function.

## Running Migrations

```bash
# Install Supabase CLI
npm install -g supabase

# Start local Supabase
supabase start

# Rebuild local database (no mock data is seeded)
supabase db reset

# Generate TypeScript types
npx supabase gen types typescript --local > src/types/database.ts

# Push to production
supabase db push
```

## RLS Tests

```bash
# Run the RLS test suite against a disposable database with its required fixtures
supabase db execute --file supabase/tests/rls_test.sql
```

All 12 tests should print `PASS`. Any `FAIL` or `WARNING` indicates a policy regression.
